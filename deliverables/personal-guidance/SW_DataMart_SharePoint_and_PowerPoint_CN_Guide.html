SW Data Mart

SharePoint Site 与 PowerPoint 中文使用说明

用途：这份说明只供你个人理解、迁移、维护与讲解使用。团队模板、SharePoint 页面和 PPT 保持英文；这份中文解释不要放到对外页面或正式规格中。

1. 一句话说明架构

SW Data Mart 的作用是：在不重复 Global EDI 上游数据工程的前提下，把已经发布的 Gold View 转成 APAC 可稳定使用、可追溯、可解释的数据产品，并交付 Dashboard、Report、权限设计及 Power Platform 集成。

Global EDI Gold View→Refined Coat (RC)→Sealer Coat (SC)→Top Coat (TC)→DA / IV / RP / EX
位置中文理解责任与输出
Global EDI Gold View上游已整理好的来源契约Global EDI 负责其数据仓库、Gold View 和上游 ETL。
RC接入并整合APAC 受控接入 Gold View，保留来源键与加载审计信息。
SC修正、标准化、补充业务规则处理数据质量、映射、例外和重复运行控制；DA 文档到这里为止。
TC供消费的数据与语义出口为 IV、RP、EX 提供稳定、业务友好的表、视图或语义模型。
语言边界：对外材料不要将 RC / SC / TC 说成一个新的企业数据仓库或 Global EDI 的重复工作。统一说：APAC consumes the Global EDI Gold View and maintains local consumption objects through Refined / Sealer / Top Coat.

2. SharePoint Site 的定位

当前 sharepoint-site 文件夹是一个可本地浏览的内容与信息架构蓝图，不是可以直接上传后自动变成 SharePoint Modern Site 的安装包。它的作用是让你在公司电脑上按相同的页面、英文内容、菜单和下载入口迁移到正式 Site。

本地页面要向谁说明什么正式 SharePoint 的建议实现
Home先让 End User 明白此架构能做什么，以及不会重复 Global EDI 的工作。Communication Site 首页；Hero、Text、Quick Links。
Request & Delivery说明 DRIVE 如何管理一个 enhancement，并指向 DA / IV / RP / EX。普通 Site Page；Text、Document Library 或 List 链接。
How Data Is Prepared说明 Gold View 到 RC / SC / TC 的数据路径与文档分工。普通 Site Page；Text、图片/流程图、Quick Links。
Trust & Governance说明四个角色的责任与决策边界。普通 Site Page；Text、List 或轻量表格。
Template Library供团队下载 Word 与 Excel 模板。Document Library 页面或 Page + Document Library Web Part。

在公司电脑上的迁移顺序

  1. 从 GitHub 下载项目，先打开 sharepoint-site/index.html 确认最新英文内容和导航。
  2. 创建 Communication Site 或使用部门既有 Site；建立五个页面：Home、Request & Delivery、How Data Is Prepared、Trust & Governance、Template Library。
  3. 以本地原型为蓝图复制英文标题、正文和流程。Home 优先放 Gold View → RC → SC → TC → outputs 的图和面向 End User 的价值说明。
  4. 建立 Document Library（建议名：SW Data Mart Templates），上传模板和最终文档；将 Template Library 页中的下载入口改为 SharePoint 文件链接。
  5. 建立与本地原型相同顺序的顶部导航；最后按真实组织权限确认访问范围。

3. 建议的 SharePoint 文档库结构

文件夹 / Library放置内容维护规则
01 — Enhancement Designs已批准的 DRIVE 文档与最终截图。每个 enhancement 一个 DRIVE ID；DRIVE 内维护 DA / IV / RP / EX 文件名或链接。
02 — Component DesignsDA、IV、RP、EX 工作文档。按 Subject Area 或 DRIVE ID 分类；发布后保留版本历史。
03 — Data FoundationsDM、DL、DD 三个 Excel 工作簿。每个 Subject Area 一套；Data Model、Lineage、Dictionary 同步更新。
04 — Templates空白 Word / Excel 模板和 DRIVE register。Technical Analyst 维护模板版本；团队下载副本后填写。
05 — Evidence & ReleaseUAT、对账、截图、发布记录。与 DRIVE ID 关联；不要放临时代码和敏感原始数据。

4. PPT 的使用逻辑

PPT 的目的不是展示所有技术细节，而是让听众按“为什么需要 → 边界在哪里 → 数据怎样流动 → 如何落地与谁负责”的顺序理解。先讲责任边界，再讲数据路径，最后讲文档与治理。

Slide中文解释讲解重点
1封面与总体定位这是受治理的 APAC 分析基础，不是新的企业数据仓库。
2Global EDI 与 APAC 的职责边界Global EDI 负责 Gold View 和上游 ETL；APAC 负责消费与下游稳定性。
3–5数据路径与三个 CoatRC 接入整合；SC 修正补充；TC 提供业务可用出口。
4 / 6–8Lineage、语义模型、对象及审计字段字段、指标、Reference / Rollup、WHO / WHEN 都可以解释和追溯。
9–10四类交付与文档包DA、IV、RP、EX 共享 TC 基础；DRIVE 是 overall enhancement design。
11四个角色只有 End User、PMO Manager、Technical Analyst、ERP Consultant。
12下一步先选 Subject Area，建设基础对象与控制证据，然后扩展可复用交付。

面对不同听众的开场

对象建议开场强调内容
End User“我们希望你更快得到一致、可解释的业务结果。”Dashboard / Report、刷新、可追溯性和 UAT。
PMO Manager“我们把 enhancement 变成可排期、可验收、可审计的交付。”DRIVE、优先级、依赖、发布和决策升级。
Technical Analyst“我们把 Gold View 的消费过程标准化，减少每个需求重复设计。”RC / SC / TC、DM / DL / DD、质量控制、权限与证据。
ERP Consultant“业务规则不会隐藏在报表中，而是被明确记录和验证。”字段定义、例外、状态映射、粒度与业务验收。

5. 发布前个人检查清单

  • Home Page 是否清楚说明 Global EDI Gold View 的责任边界？
  • 是否统一使用 Refined Coat / Sealer Coat / Top Coat，以及 RC / SC / TC？
  • DRIVE 是否列出全部适用的 DA / IV / RP / EX 文件名或链接？
  • DM、DL、DD 是否已与实际 TC 对象、字段、指标和转换逻辑同步？
  • WHO / WHEN、Reference、Rollup、业务粒度和访问限制是否已记录？
  • 角色是否只保留 End User、PMO Manager、Technical Analyst、ERP Consultant？
  • SharePoint 下载入口是否指向最新模板和最终版本文件？
  • PPT 是否先说边界与业务价值，再说架构与治理？
